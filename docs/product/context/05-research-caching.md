# Research: Frontier-lab prompt caching and server-side conversation state as of 2026 (Anthropic, OpenAI, Google Gemini, DeepSeek, Mistral, xAI): TTLs, pricing multipliers, stateful APIs, retention, and eviction statements

## Summary

As of September 2026, all six providers offer prefix-based prompt caching, but they differ in TTL, pricing, and control. Anthropic uses an explicit or automatic cache_control with a 5-minute default TTL refreshed free on each read and an optional 1-hour TTL; writes cost 1.25x (5m) or 2x (1h) base input, reads 0.1x (0.025x on Fable 5.1 / Mythos 5.1), minimum cacheable size is 512-4,096 tokens by model, and caches are isolated per organization/workspace. Community log audits attribute Claude Code cost/quota changes in March-April 2026 to a switch from 1h to 5m cache writes; no Anthropic primary statement was located. Anthropic's Managed Agents provide server-side stateful sessions billed at $0.08 per running session-hour with no idle billing.

OpenAI's caching is automatic. Pre-GPT-5.6 models use prompt_cache_retention: in_memory (5-10 minutes of inactivity, up to one hour) or 24h (about 30 minutes typical, up to 24 hours, KV tensors offloaded to GPU-local storage); non-ZDR orgs default to 24h, ZDR orgs to in_memory, with no cache-write charge and cached input at a 90% discount. GPT-5.6+ introduces a 30-minute minimum TTL, 1.25x cache-write and 0.1x read pricing, explicit breakpoints, and a 1,024-token minimum. Responses API previous_response_id still bills all prior input tokens; responses are stored 30 days by default, Conversation objects indefinitely.

Google Gemini enables implicit caching by default (2,048-4,096 token minimum, no savings guarantee) and explicit caches with a 1-hour default TTL billed as cached tokens plus hourly storage ($0.50-$4.50 per 1M tokens per hour by model). The Interactions API stores state 55 days (paid) or 1 day (free). DeepSeek caches automatically on disk with free storage, 64-token units at launch, cache hits at roughly 3% of miss price (e.g., $0.014 vs $0.44 peak on V4-Flash), and unused caches cleared 'within a few hours to a few days'. Mistral requires an opt-in prompt_cache_key, 64-token blocks, 10% cached-input pricing, and offers a stateful Conversations API without a documented retention window. xAI caches automatically keyed by x-grok-conv-id, publishes per-model cached rates (e.g., $0.50 vs $2.00 on grok-4.6), states entries may be evicted at any time without a duration guarantee, and stores responses 30 days unless ZDR is enabled.

## Facts

- (high, as of 2026-09-03) Anthropic: "By default, the cache has a 5-minute lifetime. The cache is refreshed for no additional cost each time the cached content is used." A 1-hour option is set via cache_control {"type":"ephemeral","ttl":"1h"}.  
  Source: https://platform.claude.com/docs/en/build-with-claude/prompt-caching
- (high, as of 2026-09-03) Anthropic: cache lifetime "is measured from the start of the request that writes or reads the cache entry, not from the end of its response. Time spent generating a response counts against the lifetime: if a response takes 4 minutes to stream, a follow-up request that reuses the same cached prefix must start within about 1 minute of that response completing."  
  Source: https://platform.claude.com/docs/en/build-with-claude/prompt-caching
- (high, as of 2026-09-03) Anthropic pricing multipliers: 5-minute cache write = 1.25x base input; 1-hour cache write = 2x base input; cache read/refresh = 0.1x base input, except Claude Fable 5.1 and Claude Mythos 5.1 where cache hits/refreshes are 0.025x base input ($0.25/MTok).  
  Source: https://platform.claude.com/docs/en/about-claude/pricing
- (high, as of 2026-09-03) Anthropic per-model cache pricing (base input / 5m write / 1h write / cache hit / output, per MTok): Fable 5.1 $10 / $12.50 / $20 / $0.25 / $50; Opus 5 and Opus 4.8 $5 / $6.25 / $10 / $0.50 / $25; Sonnet 5 $2 / $2.50 / $4 / $0.20 / $10; Sonnet 4.6 $3 / $3.75 / $6 / $0.30 / $15; Haiku 4.5 $1 / $1.25 / $2 / $0.10 / $5.  
  Source: https://platform.claude.com/docs/en/about-claude/pricing
- (high, as of 2026-09-03) Anthropic: Claude Sonnet 5's $2/$10 introductory pricing (through Aug 31, 2026) is now the standard price; the scheduled increase to $3/$15 on Sept 1, 2026 "will not occur."  
  Source: https://platform.claude.com/docs/en/about-claude/pricing
- (high, as of 2026-09-03) Anthropic minimum cacheable prompt length: 512 tokens (Fable 5.1, Mythos 5.1, Opus 5, Fable 5, Mythos 5); 1,024 tokens (Opus 4.8, Sonnet 5, Sonnet 4.6, Sonnet 4.5, Opus 4.1, Opus 4, Sonnet 4); 2,048 tokens (Mythos Preview, Opus 4.7, Haiku 3.5); 4,096 tokens (Opus 4.6, Opus 4.5, Haiku 4.5). Shorter prompts are processed without caching and no error is returned.  
  Source: https://platform.claude.com/docs/en/build-with-claude/prompt-caching
- (high, as of 2026-09-03) Anthropic: up to 4 cache breakpoints per request; the automatic lookback window is 20 blocks per breakpoint; if 4 explicit breakpoints already exist and automatic caching is requested, the API returns a 400 error. Automatic caching is enabled with a single top-level cache_control field that "automatically applies the cache breakpoint to the last cacheable block and moves it forward as conversations grow."  
  Source: https://platform.claude.com/docs/en/build-with-claude/prompt-caching
- (high, as of 2026-09-03) Anthropic: when mixing TTLs, "Cache entries with longer TTL must appear before shorter TTLs (that is, a 1-hour cache entry must appear before any 5-minute cache entries)." Cache hierarchy is tools -> system -> messages; changes at a level invalidate that level and all subsequent levels; modifying tool definitions invalidates the entire cache.  
  Source: https://platform.claude.com/docs/en/build-with-claude/prompt-caching
- (high, as of 2026-09-03) Anthropic cache isolation: "Caches are isolated between organizations. Different organizations never share caches, even if they use identical prompts." Caches are also isolated per workspace on the Claude API, Claude Platform on AWS, and Microsoft Foundry; Bedrock and Google Cloud use organization-level isolation only.  
  Source: https://platform.claude.com/docs/en/build-with-claude/prompt-caching
- (high, as of 2026-09-03) Anthropic: caching multipliers stack with the Batch API 50% discount and the 1.1x data-residency multiplier (inference_geo: "us", Claude 4.6+). Claude 4.6+ models include the full 1M-token context window at standard pricing, and "Prompt caching and batch processing discounts apply at standard rates across the full context window."  
  Source: https://platform.claude.com/docs/en/about-claude/pricing
- (high, as of 2026-09-03) Anthropic docs do not describe idle-session eviction separate from the TTL, nor any behavior on expiry other than a cache miss followed by a new cache write; the 1-hour cache 'refresh' on read is free, same as 5-minute.  
  Source: https://platform.claude.com/docs/en/build-with-claude/prompt-caching
- (high, as of 2026-09-03) Anthropic Claude Managed Agents (server-side stateful sessions, beta header managed-agents-2026-04-01) bill tokens at standard model rates with prompt-caching multipliers applying identically, plus session runtime at $0.08 per session-hour metered only while status is 'running'; time spent 'idle', 'rescheduling', or 'terminated' is not billed. Batch discount does not apply.  
  Source: https://platform.claude.com/docs/en/about-claude/pricing

- (high, as of 2026-09-03) OpenAI GPT-5.6 and later: minimum cacheable prefix 1,024 tokens; prompt_cache_options.ttl has one supported value, "30m", which is the default; "A cached prefix remains eligible for reuse for 30 minutes after its most recent write or reuse, though OpenAI may retain it longer"; cache writes cost 1.25x the uncached input rate and cache reads 0.1x.  
  Source: https://developers.openai.com/api/docs/guides/prompt-caching
- (high, as of 2026-09-03) OpenAI models before GPT-5.6: minimum 2,048 visible input tokens ("some models may cache shorter prefixes"); prompt_cache_retention values: in_memory ("Entries typically remain active for around 5 to 10 minutes of inactivity, up to one hour") and 24h ("typically keeps entries available for around 30 minutes and can retain them for up to 24 hours"); no additional cache-write charge.  
  Source: https://developers.openai.com/api/docs/guides/prompt-caching
- (high, as of 2026-09-03) OpenAI default retention for models supporting both policies: "Organizations without Zero Data Retention enabled default to 24h. Organizations with Zero Data Retention enabled default to in_memory."   Source: https://developers.openai.com/api/docs/guides/prompt-caching
- (high, as of 2026-09-03) OpenAI cookbook 'Prompt Caching 201': "For gpt-5.5, gpt-5.5-pro, and all future models, the default is 24h"; requests are routed by a hash of the first ~256 tokens combined with prompt_cache_key; inference engines handle "roughly ~15 requests per minute per prefix + prompt_cache_key combination" before overflow to other machines; one customer example improved hit rate from 60% to 87%; TTFT was 67% faster for 150k+ token prompts.  
  Source: https://developers.openai.com/cookbook/examples/prompt_caching_201
- (high, as of 2026-09-03) OpenAI prompt_cache_key "influence[s] routing; they do not pin requests to a machine or guarantee a cache read hit"; "When traffic exceeds a machine's available capacity, requests may overflow to another machine. If that machine does not have a matching cache entry, the initial overflow request incurs a cache miss."  
  Source: https://developers.openai.com/api/docs/guides/prompt-caching
